# Design Software Architecture

1. Confirmar alcance funcional y restricciones.
2. Ejecutar entrevista de Software Architect.
3. Priorizar atributos de calidad y escenarios medibles.
4. Aplicar `knowledge-packs/architecture/styles-and-patterns.md` y paquetes técnicos seleccionados.
5. Preferir la solución más simple que satisfaga drivers conocidos.
6. Definir contexto, límites, propiedad de datos, contratos e integraciones.
7. Modelar fallas, seguridad, observabilidad y recuperación.
8. Crear ADR para decisiones significativas usando `docs/templates/adr.md`.
9. Identificar spikes para incertidumbre alta y controles para límites verificables.
10. Entregar restricciones claras a backend, frontend, QA y plataforma.
