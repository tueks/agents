# Document Product

1. Ejecutar entrevista de Project Documentarian si faltan audiencia, fuentes o propietarios.
2. Tratar documentos aprobados del repositorio como fuente de verdad.
3. Actualizar `docs/product/product-overview.md` con resúmenes y enlaces, no duplicación extensa.
4. Mantener índices, glosario y vínculos entre versiones, ADRs, UX, ingeniería, QA y operación.
5. Señalar contradicciones al propietario; no decidir contenido especializado por cuenta propia.
6. Registrar estado, vigencia, propietario y última revisión cuando sea útil.
7. Proponer plataforma externa solo para consumo o colaboración; mantener decisiones esenciales versionadas o enlazadas de forma estable.
8. Verificar que un nuevo integrante pueda comprender propósito, estado, arquitectura y operación básica.
