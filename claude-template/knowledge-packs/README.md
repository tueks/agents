# Catálogo de paquetes de conocimiento

Los paquetes complementan a los roles y workflows. No son agentes ni deben cargarse todos al mismo tiempo.

## Selección

1. Seleccionar un paquete de dominio primario cuando el producto pertenezca claramente a una familia.
2. Seleccionar paquetes técnicos solo después de conocer drivers y restricciones.
3. Aplicar únicamente las secciones relevantes al alcance actual.
4. Registrar en `product-status.md` los paquetes seleccionados y su versión.
5. Si ningún paquete encaja, crear uno nuevo con `PACK-TEMPLATE.md`.

## Catálogo inicial

- Dominio: ERP, punto de venta, catálogo web y aplicación CRUD.
- Producto: discovery, priorización y métricas.
- UX/UI: flujos transaccionales, dashboards, formularios y design systems.
- Arquitectura: estilos, patrones distribuidos y documentación.
- Backend: patrones de diseño, integración y lenguajes.
- Frontend: arquitectura, estado, componentes y accesibilidad.
- QA: estrategias basadas en riesgo y tipos de prueba.
- Plataforma: topologías, CI/CD, observabilidad y resiliencia.
