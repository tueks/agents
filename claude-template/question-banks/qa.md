# Banco de preguntas: QA Engineer

## Riesgo y alcance

1. ¿Qué comportamientos y resultados debe garantizar esta versión?
2. ¿Qué fallas causarían mayor daño al usuario o negocio?
3. ¿Qué áreas cambiaron y cuáles podrían sufrir regresión indirecta?
4. ¿Qué plataformas, roles, regiones y configuraciones deben cubrirse?
5. ¿Qué partes no se probarán y qué riesgo se acepta?

## Criterios y trazabilidad

6. ¿Cada requisito tiene criterios verificables?
7. ¿Qué ejemplos y contraejemplos aclaran las reglas?
8. ¿Qué estados, límites y errores deben incluirse?
9. ¿Cómo se vinculan requisitos, pruebas, defectos y resultados?

## Estrategia

10. ¿Qué debe cubrirse con pruebas unitarias, integración, contrato, E2E y exploratorias?
11. ¿Qué pruebas deben automatizarse ahora?
12. ¿Qué datos, fixtures, mocks o ambientes se necesitan?
13. ¿Cómo se evita que las pruebas dependan de orden o estado compartido?
14. ¿Qué pruebas de accesibilidad, seguridad y rendimiento aplican?

## No funcionales y operación

15. ¿Qué carga, latencia y estabilidad deben comprobarse?
16. ¿Qué fallos de dependencias o red deben simularse?
17. ¿Cómo se verifica observabilidad, alertas y auditoría?
18. ¿Cómo se prueba migración, rollback y recuperación?

## Release gate

19. ¿Qué defectos bloquean la liberación?
20. ¿Quién acepta riesgos conocidos?
21. ¿Qué evidencia debe acompañar la aprobación?
22. ¿Qué smoke tests se ejecutan después del despliegue?
23. ¿Qué señales activan rollback?

## Criterios de salida

- Riesgos y alcance de prueba definidos.
- Trazabilidad entre requisitos y pruebas disponible.
- Pirámide o estrategia de pruebas proporcional al producto.
- Ambientes, datos y automatización identificados.
- Criterios de bloqueo, aceptación y rollback acordados.
- Resultado de release gate auditable.
