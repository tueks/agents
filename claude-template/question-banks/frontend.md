# Banco de preguntas: Frontend Engineer

## Experiencia y alcance

1. ¿Qué journeys, pantallas y estados están aprobados?
2. ¿Qué plataformas y navegadores deben soportarse?
3. ¿Qué breakpoints o dispositivos son prioritarios?
4. ¿Qué funcionalidad debe operar sin conexión o con red inestable?

## Componentes y estado

5. ¿Existe sistema de diseño o biblioteca de componentes?
6. ¿Qué componentes deben ser reutilizables?
7. ¿Qué estado es local, compartido, derivado o persistente?
8. ¿Cómo se representan loading, empty, error, success y permisos insuficientes?
9. ¿Qué acciones necesitan optimismo, deshacer o confirmación?

## Integración

10. ¿Qué contratos de backend consume cada flujo?
11. ¿Cómo se gestionan autenticación, sesión y renovación?
12. ¿Cómo se muestran errores técnicos frente a errores de negocio?
13. ¿Se requieren tiempo real, polling, archivos o cargas grandes?
14. ¿Cómo se mantiene compatibilidad durante despliegues independientes?

## Accesibilidad, contenido y seguridad

15. ¿Qué estándar de accesibilidad aplica?
16. ¿Se soportan teclado, lectores de pantalla y reducción de movimiento?
17. ¿Hay internacionalización, moneda, fecha o zona horaria?
18. ¿Qué datos sensibles nunca deben persistirse en el cliente?
19. ¿Qué entradas requieren validación y prevención de abuso?

## Calidad y operación

20. ¿Qué pruebas de componentes, integración y E2E son necesarias?
21. ¿Qué presupuestos de rendimiento se establecen?
22. ¿Qué telemetría de uso y errores se permite recopilar?
23. ¿Cómo se construye, configura y despliega el frontend?
24. ¿Qué feature flags o variantes existen?

## Criterios de salida

- Mapa de pantallas, estados y componentes definido.
- Estrategia de estado e integración clara.
- Accesibilidad, responsive y seguridad contempladas.
- Pruebas y rendimiento acordados.
- Handoff UX y contratos backend trazables.
