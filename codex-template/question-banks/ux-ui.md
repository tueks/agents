# Banco de preguntas: UX/UI Designer

## Contexto de uso

1. ¿Quiénes son los usuarios primarios y qué intentan conseguir?
2. ¿Dónde, cuándo y con qué dispositivos usan el producto?
3. ¿Qué nivel de experiencia tienen con sistemas similares?
4. ¿Qué frustraciones presentan las soluciones actuales?
5. ¿Existen limitaciones de conectividad, tiempo, movilidad o accesibilidad?

## Arquitectura de información y journeys

6. ¿Cuál es el journey principal del MVP?
7. ¿Qué información necesita el usuario en cada paso?
8. ¿Qué conceptos y términos entiende el usuario?
9. ¿Qué contenido debe encontrarse con mayor rapidez?
10. ¿Qué roles ven opciones diferentes?
11. ¿Qué estados vacíos, de carga, error y éxito deben diseñarse?

## Interacción

12. ¿Qué acciones son frecuentes, críticas o difíciles de revertir?
13. ¿Qué acciones requieren confirmación?
14. ¿Qué tareas deben completarse con el menor número de pasos?
15. ¿Se necesita búsqueda, filtrado, ordenamiento o trabajo masivo?
16. ¿Se requiere funcionamiento responsive, táctil o con teclado?
17. ¿Qué feedback inmediato debe recibir el usuario?

## Lenguaje visual

18. ¿Existe marca, logotipo, paleta, tipografía o sistema de diseño?
19. ¿Qué atributos debe comunicar visualmente el producto?
20. ¿Hay productos de referencia y qué aspectos interesan de ellos?
21. ¿Qué densidad de información necesita cada tipo de pantalla?
22. ¿Se necesita tema claro, oscuro o ambos?

## Accesibilidad y contenido

23. ¿Qué nivel de accesibilidad se requiere?
24. ¿Existen idiomas, lectura simplificada o contenido sensible?
25. ¿Quién redactará etiquetas, ayudas, errores y onboarding?
26. ¿Qué información nunca debe depender solo del color?

## Validación

27. ¿Se dispone de usuarios para entrevistas o pruebas?
28. ¿Qué hipótesis UX son más riesgosas?
29. ¿Qué puede validarse con wireframes antes de desarrollar?
30. ¿Quién aprueba los flujos y la guía visual?

## Criterios de salida

- Usuarios, contexto y journey principal definidos.
- Arquitectura de información y navegación descritas.
- Estados y errores críticos contemplados.
- Principios visuales, responsive y accesibilidad establecidos.
- Hipótesis y método de validación registrados.
- Handoff a frontend suficientemente concreto.
