# Plan Version Change

1. Crear un change request desde `docs/templates/change-request.md`.
2. Clasificar tipo, urgencia, valor, riesgo y tamaño desconocido.
3. Solicitar análisis solo a roles potencialmente afectados.
4. Consolidar impacto sin ocultar desacuerdos.
5. Definir alcance incluido, exclusiones, criterios de aceptación y compatibilidad.
6. Dividir cambios grandes en incrementos verificables.
7. Definir migración, feature flags, rollout y rollback cuando apliquen.
8. Crear la especificación con `docs/templates/version-specification.md`.
9. Verificar Definition of Ready antes de implementación.
