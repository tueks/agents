# Design Backend

1. Confirmar casos de uso y criterios de aceptación.
2. Ejecutar entrevista Backend.
3. Aplicar paquetes de dominio, arquitectura y `knowledge-packs/backend/patterns-and-languages.md`.
4. Seguir patrones existentes del repositorio antes de introducir nuevos.
5. Definir contratos, errores, compatibilidad e idempotencia.
6. Definir invariantes, transacciones, concurrencia y propiedad de datos.
7. Diseñar integraciones con timeout, retry, compensación y observabilidad explícitos.
8. Incluir autorización, protección de datos y auditoría.
9. Definir pruebas unitarias, integración, contrato y rendimiento proporcionales al riesgo.
10. Registrar decisiones significativas y evitar abstracciones especulativas.
